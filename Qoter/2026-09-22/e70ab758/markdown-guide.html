1. 什么是 Markdown

用纯文本写出格式漂亮的文档

Markdown 是一种轻量级标记语言,由 John Gruber 于 2004 年创建。它让你用简单的符号(如 #、*、-)来标记文本格式,写作时专注内容,渲染后自动变成漂亮的排版。

它被广泛用于:GitHub 的 README、技术文档、博客、笔记软件(如 Notion、Obsidian、语雀)、聊天工具等。

核心理念:源文件即使不渲染,也应该清晰易读。语法越少越好,越接近自然书写越好。
提示:Markdown 有多种"方言"。最常见的是 CommonMark 标准和 GitHub Flavored Markdown (GFM)。本手册的"进阶语法"部分主要基于 GFM。

18. 实用技巧与最佳实践

写出更规范、更兼容的 Markdown

推荐做法

  • 符号后留空格:#、-、> 后都要留一个空格,兼容性最好。
  • 段落间留空行:标题、列表、代码块、表格前后都建议留空行,避免解析歧义。
  • 统一风格:强调统一用 *,列表统一用 -,全篇保持一致。
  • 代码块标注语言:如 ```js、```python,可获得语法高亮。
  • 图片写好 alt 文字:利于无障碍与加载失败时的提示。

常见坑

  • 单词中间用 _ 做强调可能失效(如 a_b_c),改用 *。
  • 直接回车不会换行,需要空行分段或行尾两个空格。
  • 脚注、任务列表等属于扩展语法,换平台前先确认是否支持。
  • 表格、列表如果前面没有空行,可能不会被识别。

推荐工具

  • 编辑器:Typora、Obsidian、VS Code(装 Markdown 插件)、语雀。
  • 在线练习:可搜索 "Dillinger"、"StackEdit"、"Markdown Live Preview" 等实时预览工具。
  • 标准参考:CommonMark 官方规范、GitHub Flavored Markdown Spec。
学习建议:Markdown 的语法量很小,最好的学习方式就是打开一个编辑器,把本手册里的每个例子亲手敲一遍,10 分钟就能掌握 90% 的日常用法。
