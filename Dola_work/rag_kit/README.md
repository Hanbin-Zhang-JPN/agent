# rag_kit — 白箱（ホワイトボックス）RAG

日本語で作られた、**仕組みが全て理解できる** 軽量 RAG（Retrieval-Augmented
Generation）のリファレンス実装です。外部ブラックボックス依存なしで、
「文書の登録 → チャンク分割 → 索引構築 → ハイブリッド検索 → 再ランキング
→ 回答生成」までを一通り動かせます。

---

## 1. このプロジェクトの目的

- **RAG の中身を全て透明にする**：検索・ベクトル化・ランキングの計算を
  外部ライブラリに隠さず、1行ずつ日本語コメント付きで公開します。
- **追加学習なしで専門知識を扱う**：文書を登録するだけで、その内容を
  根拠付きで回答できる仕組みを提供します。
- **実用的な性能を標準ライブラリだけで実現**：BM25 と n-gram ベクトルを
  組み合わせたハイブリッド検索により、表記ゆれや類義語にも対応します。

## 2. 主な特徴

| 項目 | 内容 |
|------|------|
| 依存 | 本体は **Python 標準ライブラリのみ**（numpy / 深層学習不要） |
| 検索 | BM25（キーワード）＋ n-gram ベクトル（類似度）の **ハイブリッド** |
| 統合 | RRF（Reciprocal Rank Fusion）による順位融合 |
| 品質 | 軽量再ランカー、任意で MMR による多様化 |
| 生成 | 抽出型（LLM不要）と OpenAI 互換 API 型（任意）の2系統 |
| 評価 | Accuracy@k を測る評価スクリプト付き |
| 言語 | ソースコード・README ともに日本語の詳細コメント |

## 3. フォルダ構成

```
rag_kit/
├── README.md          # この説明書
├── requirements.txt   # 依存定義（必須なし・任意のみ）
├── rag/               # RAG 本体（パッケージ）
│   ├── __init__.py    # パッケージ入口（RagPipeline を公開）
│   ├── tokenizer.py   # トークナイザー（CJK/英単語・n-gram）
│   ├── loader.py      # 文書読み込み（txt / md / csv、任意で PDF）
│   ├── chunker.py     # チャンク分割（段落・重複・見出し追跡）
│   ├── vectors.py     # ベクトル化（FNV-1a / TF-IDF / コサイン）
│   ├── index.py       # BM25 索引とコーパス保存
│   ├── retriever.py   # ハイブリッド検索（BM25+ベクトル・RRF・MMR）
│   ├── reranker.py    # 軽量再ランキング（被覆率・長さ・見出し）
│   ├── generator.py   # 回答生成（抽出型 / LLM型）
│   └── pipeline.py    # パイプライン統合（ビルド→質問応答）
├── app/               # 実行ツール
│   ├── cli.py         # コマンドライン（build / ask / stats）
│   ├── eval.py        # 検索精度の評価（Accuracy@k）
│   └── demo.py        # 対話型デモ
├── data/              # サンプル文書（RAG 解説の日本語マークダウン）
├── out/               # 構築された索引の保存先
└── tests/             # 単体テスト（unittest）
```

フォルダ名は短く・内容が一目で分かるようにしています。
`rag`＝本体、`app`＝ツール、`data`＝入力文書、`out`＝出力、`tests`＝テスト。

## 4. 全体の流れ（アーキテクチャ）

```
                ┌──────────────────────────────────────────┐
  文書登録      │  loader.py  読み込み                       │
                │    ↓                                     │
                │  chunker.py チャンク分割（重複・見出し）    │
                │    ↓                                     │
  索引構築      │  tokenizer.py → index.py(BM25)            │
                │              → vectors.py(TF-IDF+正規化)  │
                └──────────────────────────────────────────┘
                               ↓ 保存（out/ へ JSON）
                ┌──────────────────────────────────────────┐
  質問応答      │  retriever.py   BM25 + ベクトル → RRF      │
                │      ↓  （任意 MMR で多様化）              │
                │  reranker.py   被覆率・長さ・見出しで再ランク│
                │      ↓                                    │
                │  generator.py  抽出型 / LLM型で回答＋出典  │
                └──────────────────────────────────────────┘
```

## 5. 各モジュールの解説

### rag/tokenizer.py — トークナイザー
- 日本語・中国語の **CJK 文字は1文字=1トークン**、英数字は単語単位に分解。
- 検索には「語彙トークン」（完全一致用）と「n-gram 特徴量」（類似度用）の
  2種類を生成します。n=2 の bi-gram が日本語で実用的な精度を出します。

### rag/loader.py — 文書読み込み
- `.txt` / `.md` / `.csv` を複数の文字コードから自動判定して読み込みます。
- PDF は **任意のオプション**（pypdf を導入した場合のみ有効）です。

### rag/chunker.py — チャンク分割
- 空行を区切りに段落へ分解し、目標文字数を超えたらチャンクを確定。
- 前チャンクの末尾を **オーバーラップ** として引き継ぎ、文脈の切れ目を防止。
- 見出し（`#` / `【】`）をメタデータとして記録。超長い段落は文単位で分割。

### rag/vectors.py — ベクトル化
- n-gram 特徴量を **FNV-1a ハッシュ** で固定次元（既定 4096）へ写像。
- **TF-IDF** 重み付け（出現頻度×希少度）で文書をスパースベクトル化。
- 文書間の類似度は **コサイン類似度** で計算。保存・復元も可能。

### rag/index.py — BM25 索引
- 転置索引（語→文書リスト）を使った古典的 BM25 検索。
- パラメータ k1=1.5 / b=0.75 は標準値。コーパス（チャンク本文）も保存。

### rag/retriever.py — ハイブリッド検索
- BM25 の順位と、n-gram ベクトルのコサイン順位を **RRF** で融合。
- `mmr_lambda>0` にすると **MMR** により回答の多様性を確保します。

### rag/reranker.py — 軽量再ランキング
- クエリ語の**被覆率**、チャンク長の**罰則**、**見出しボーナス** を
  合成して上位を並べ替えます。重みはコード内の定数で調整可能。

### rag/generator.py — 回答生成
- **抽出型（既定）**：LLM を使わず、最適チャンクの要点を引用して回答。
- **LLM型（任意）**：OpenAI 互換 API に `urllib`（標準ライブラリ）で
  HTTP 送信。引用番号付きの回答を要求するプロンプトを使用します。

### rag/pipeline.py — パイプライン統合
- `build_dir()` で索引を構築し、`ask()` で質問に回答する一連の流れを束ねます。
- 索引は `out/` へ JSON で保存でき、`load()` で再開できます。

## 6. インストールと使い方

### 6-1. 依存（必要なし）
Python 3.9 以降のみ。`pip install` は不要です。

### 6-2. 索引を構築する
```bash
cd rag_kit
python3 app/cli.py build data out
```
`data/` 内の文書がチャンク化され、`out/` に索引が保存されます。

### 6-3. 質問に回答する
```bash
python3 app/cli.py ask out "RAGとは何ですか？"
```
抽出型で回答と出典一覧が表示されます。

### 6-4. 対話デモ
```bash
python3 app/demo.py data out
```
対話形式で繰り返し質問できます（終了は `quit`）。

### 6-5. 評価する
```bash
python3 app/eval.py out --top-k 3
```
サンプル文書では Accuracy@3 = 100%、Accuracy@1 = 80% を確認できます。

## 7. LLM（生成モデル）と連携するには

生成を LLM に任せたい場合は、環境変数を設定して `--llm` を付けます。

```bash
export RAG_LLM_URL="https://api.openai.com/v1"
export RAG_LLM_KEY="sk-xxxx"
export RAG_LLM_MODEL="gpt-4o-mini"   # 省略可（既定値あり）
python3 app/cli.py ask out "RAGとは何ですか？" --llm
```

- 通信は標準ライブラリ `urllib` のみで行います（追加依存なし）。
- 環境変数が無い場合は、分かりやすいエラーメッセージで案内します。

## 8. テスト

```bash
cd rag_kit
python3 -m unittest discover -s tests -v
```
トークナイザー / チャンク分割 / ベクトル / BM25 / パイプライン全体を
25 件のテストで検証しています。

## 9. 制限と拡張の方向

- **規模**：数十〜数千チャンク向け。さらに大規模な場合は候補絞り込みや
  numpy 化・外部ベクトル DB の併用を検討します。
- **意味理解**：n-gram ベクトルは表記ゆれに強い一方、深い意味理解は
  LLM 型生成に委ねます。
- **拡張ポイント**：`reranker.py` の重み、`chunker.py` のサイズ、
  `retriever.py` の融合方法などを用途に応じて調整してください。
