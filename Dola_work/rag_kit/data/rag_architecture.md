# RAGの構成要素

【チャンク分割】
RAG では長い文書をそのまま使わず、検索しやすい単位へ分割します。
この単位を「チャンク」と呼びます。
チャンクの大きさは検索精度に大きく影響します。小さすぎると文脈が不足し、大きすぎると不要な情報が混ざります。
一般的には数百文字程度が目安で、前後のチャンクと一部を重複させる「オーバーラップ」を設定することで、文脈の切れ目を防ぎます。

【検索モデル】
検索には大きく分けて2つの方式があります。
1つはキーワードベースの「BM25」で、質問の語が文書にどれだけ含まれるかを数えてスコア化します。
もう1つはベクトルベースの検索で、文書を数値ベクトルに変換し、質問ベクトルとの類似度で関連性を測ります。
BM25 は確実な一致に強く、ベクトル検索は表記ゆれや類義表現に強いという特徴があります。

【ハイブリッド検索】
近年の実運用では、この2つの方式を組み合わせた「ハイブリッド検索」が主流です。
キーワード検索とベクトル検索の両方の結果を統合することで、どちらか一方の弱点を補えます。
統合方法としては、順位を重み付きで足し合わせる「RRF（Reciprocal Rank Fusion）」が広く使われています。

【生成の工夫】
検索結果をそのまま生成モデルへ渡すのではなく、工夫を加えることがあります。
複数の候補から多様な情報を選ぶ「MMR」や、より関連性の高い文書を上位に並べ直す「再ランキング」です。
これらを組み合わせることで、最終的な回答の品質が大きく向上します。
