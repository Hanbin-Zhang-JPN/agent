# RAG入門

【RAGとは】
RAG とは Retrieval-Augmented Generation の略で、検索（Retrieval）と生成（Generation）を組み合わせた手法です。
あらかじめ大量の文書をインデックス化しておき、質問が来たら関連する文書を検索し、その文書を根拠として回答を生成します。
これにより、モデルが学習していない最新情報や社内文書についても、正確に答えられるようになります。

【RAGが必要な理由】
大規模言語モデル（LLM）は膨大な知識を持つ一方で、学習時点の情報しか持っていません。
そのため、最新のニュースや企業内部の資料を直接は答えられないことがあります。
RAG は検索で得た文書を参照させることで、この課題を解決します。
また、回答の根拠を明示できるため、誤った情報を自信を持って語る「幻覚」を抑える効果もあります。

【RAGの基本フロー】
RAG の流れは大きく3つのステップに分かれます。
1つ目は「インデックス構築」で、文書を小さなチャンクに分割し、検索しやすい形で保存します。
2つ目は「検索」で、質問に最も関連するチャンクを探し出します。
3つ目は「生成」で、検索したチャンクを参照しながら自然な回答を作ります。
この一連の流れを1つのシステムとして組み合わせたものが RAG です。

【RAGの利点】
RAG の最大の利点は、専門知識を追加学習なしで活用できることです。
新しい文書を追加するだけで、その情報を回答に反映できます。
また、参照元を明示できるため、回答の信頼性を高められます。
導入の手軽さと拡張のしやすさから、カスタマーサポートや社内ナレッジベースなど多くの分野で使われています。
