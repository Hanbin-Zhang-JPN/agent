R · 检索

相关，并不等于正确。

BM25 看关键词的稀有程度与频次；TF-IDF 用词法向量比较方向；Embedding 可以捕捉语义接近。所有分数都只表示排序偏好，不能当作答案正确率。

cos(q, d) = q·d / (‖q‖ ‖d‖)
A · 增强

把证据放进上下文。

RRF 根据名次融合两路检索：在两路都靠前的片段更占优势。合并后去掉大量重叠的片段，再按字符预算选取完整块。

RRF(d) = Σ 1 / (60 + rank(d))
G · 生成

模型组织语言，证据约束事实。

生成模型接收问题与选中的原文，按来源编号引用。程序检查编号是否存在，但这不能证明每句话符合原文；仍需人工检查事实与适用条件。

answer = LLM(question, evidence)

实验 01 分块可视化

CHUNKING PLAYGROUND

试试 180 与 500 字符。观察同一句话是否跨块，以及重叠重复了多少内容。预览不会修改资料库。

实验 02 检索对照评测

EVALUATE, THEN ITERATE

用同一组问题、同一份知识库比较 BM25、TF-IDF 与混合检索。默认 10 道题基于虚构示例，使用前先加载示例。也可以换成你的标准证据。

编辑评测集 JSON ＋

expected_source 为文档名，expected_quote 为应命中的原文短语；无答案题用 expected_source: null。

一条可以亲手完成的学习路线

  1. 提问并展开检索过程，追踪一个 [S1] 从原文到答案的路径。
  2. 在实验 01 改变块大小，再在资料库对某份文档重新分块。
  3. 在实验 02 用 Top 1 与 Top 4 对照；检查未命中的题，区分检索问题与资料缺失。
  4. 提一个资料没有答案的问题，观察字面相似如何造成误召回。
  5. 接入语义向量后，试问“新版本出了问题怎么办”，比较它与关键词模式。

进阶：替换中文分词器、加入重排序、做版本过滤，然后用真实评测集验证变化。

接入模型

本地检索无需 Key。要开启模型归纳或语义向量，请停止服务，在启动它的终端设置以下环境变量，再重启。

export OPENAI_API_KEY='你的 API Key'
export OPENAI_MODEL='你账户可用的 Responses 模型名称'
export OPENAI_EMBEDDING_MODEL='text-embedding-3-small'
python3 server.py --demo

API Key 仅保存在服务端环境，不会传给网页。接入后，在资料库点击“构建语义向量”，再将检索设置中的向量类型切为“模型 Embedding”。生成回答可独立开启。

默认使用 OpenAI API。自定义 OPENAI_BASE_URL 需同时支持 /embeddings 与 /responses，且使用 HTTPS。构建向量会外发资料；归纳回答会外发问题和选中证据。
