# 知有 · RAG 实验室

一个可以用于个人笔记、会议纪要、项目说明和团队手册的本地知识库，同时让 RAG 的每一步可见、可修改、可评测。

基础版只需 Python 3.10+，没有必装第三方依赖。中文界面，SQLite 持久化，原生 JavaScript 前端。适合小型资料库和教学；共享团队资料也可以导入，但此版本的服务面向本机个人使用。

## 先跑起来

```bash
cd /Users/hanbin_zhang/agent/Codex/rag-lab
./run.sh --demo
```

打开 <http://127.0.0.1:8765>。`--demo` 导入 4 份**虚构**团队手册和 8 个片段，相同内容自动跳过。不要把示例制度当作真实政策。

`run.sh` 优先使用项目 `.venv`，然后使用本机可用的 Codex 内置 Python（包含 PDF 依赖），最后回退到 `python3`。也可以直接执行 `python3 server.py --demo`，或用 `RAG_PYTHON=/路径/python3 ./run.sh --demo` 指定解释器。

初次体验可以问：“灰度发布时什么条件触发回滚？”然后点击 `[S1]` 查看原文，展开“完整过程”观察查询词、两路召回、RRF 和上下文。

不用示例时运行 `python3 server.py`。换端口用 `--port 8766`，换数据库用 `--db /绝对路径/knowledge.db`。`Ctrl+C` 停止服务；关闭网页不会删除数据。默认数据库位于 `data/knowledge.db`，已加入 `.gitignore`。

## 真实使用

1. 在“资料库”导入 TXT、Markdown、DOCX，或者直接粘贴笔记。单文件上限 8 MB，提取后的文本上限 500,000 字符；整个库最多 3,000 个片段。
2. 在“知识问答”选择资料范围、检索方式、Top K 和上下文预算，输入明确的问题。
3. 先读原文证据，核对日期、条件和适用范围。每个片段都有文档名、序号和精确字符位置，点击“查看原文”会高亮。
4. 文档改版时删除旧索引，再导入新版。同一份文档可在原文窗口重新分块；旧语义向量会失效，需要重建。
5. 对重要资料建立自己的评测题，记录文档名与标准证据短语。参数变化后用同一组题比较。

导入不会扫描你的电脑或读取其他文件，只有你选中的文件/粘贴内容进入资料库。原始文件不受删除索引影响。库内容未加密，保护好本机和数据库备份。旧问答结果在当前页面内是当时证据的快照；刷新后不会保存问答历史。结果可导出 JSON，其中包含问题与原文证据。

### PDF

文本型 PDF 使用可选 `pypdf`：

```bash
python3 -m venv .venv
source .venv/bin/activate
python3 -m pip install -r requirements-pdf.txt
python3 server.py --demo
```

重启后网页会显示 PDF 可用。PDF 最多 500 页；保留页标记，但不保留原始版面。扫描件需先 OCR；复杂表格、分栏及 DOCX 表格关系可能在纯文本提取中丢失。提问前应检查“原文与分块”。DOCX 默认提取正文段落，不提取图片、页眉和附件。

## 两种运行方式

| 能力 | 无 Key 的本地模式 | 配置模型后的可选能力 |
| --- | --- | --- |
| BM25 关键词检索 | 可用 | 可用 |
| TF-IDF 词法向量 + 余弦 | 可用 | 可用 |
| 模型 Embedding 语义向量 | 不可用 | 需先构建索引 |
| RRF 混合检索 | BM25 + TF-IDF | BM25 + 模型向量 |
| 证据摘录、来源追溯 | 可用 | 可用 |
| 大模型归纳回答 | 不可用 | 单独开启 |
| 分块实验、本地检索评测 | 可用 | 可用 |

**本地摘录是检索与阅读辅助，没有调用生成模型，也不是完整的 LLM RAG。** TF-IDF 是词法向量，不理解同义改写。接入 Embedding 与生成模型后，才是完整的语义 RAG 路径。两者都保留，是为了能用同一个系统比较并学习。

### 接入 OpenAI 模型

在启动服务的终端设置环境变量：

```bash
export OPENAI_API_KEY='你的 API Key'
export OPENAI_MODEL='你账户可用的 Responses 模型名称'
export OPENAI_EMBEDDING_MODEL='text-embedding-3-small'
python3 server.py --demo
```

生成模型不预设，填写你账户实际可用的名称。Key 只用于服务端请求，不传给浏览器，也不写入数据库。

- **语义检索**：在“资料库”点击“构建语义向量”，完成后在问答页选择“模型 Embedding”。文档向量每批 32 个，批次成功即持久化；失败后重试会跳过已完成的内容。模型或接口地址改变时向量失效，必须重建。查询向量在线生成，因此语义检索本身也需要 API。
- **生成回答**：勾选“使用大模型归纳回答”。可搭配 BM25、本地 TF-IDF 或语义向量使用。模型故障、输出不完整、引用缺失或编号越界时，回退到本地证据摘录，并显示原因。无证据时不调用生成模型。
- 构建向量会发送文档片段；语义检索会发送问题；生成会发送问题与选中证据。这些动作可能产生 API 费用，默认均关闭。先确认资料允许发送到配置的服务商。`store: false` 不应理解成服务商层面的零数据保留承诺。
- 可通过 `OPENAI_BASE_URL` 更换兼容 HTTPS 接口，默认 `https://api.openai.com/v1`。必须支持 `/embeddings` 与 `/responses`；只支持 Chat Completions 的服务不能直接使用。

接口根据 [OpenAI Embeddings 文档](https://developers.openai.com/api/docs/guides/embeddings)和 [OpenAI 文本生成文档](https://developers.openai.com/api/docs/guides/text)实现。此交付未使用付费 API 实际联调；请求构造、响应解析、向量流程和失败回退均以模拟响应测试。具体模型权限、额度及兼容服务的行为需接入后验证。

## 看懂实现

```text
文件 / 笔记
  → 提取纯文本 → 按段落/句子边界分块 → 保存来源与字符位置
  → SQLite：文档、词频、可选模型向量

问题
  → BM25 候选 ──────────┐
  → TF-IDF / Embedding ─┴→ RRF → Top K → 同源重叠去重 → 字符预算
  → 证据摘录 / LLM(问题 + 证据) → 引用编号检查 → 原文追溯
```

推荐阅读顺序：

| 文件 / 函数 | 学什么 |
| --- | --- |
| `raglab/core.py::tokenize` | 中文单字/二元字组与英文词；简化分词的优劣 |
| `split_text` | 块大小、重叠、边界与精确 offset |
| `Store` | 去重、事务、SQLite 持久化、索引版本 |
| `retrieve` | BM25、TF-IDF、余弦、RRF 的直接实现 |
| `build_context` | 重叠去重与完整块预算 |
| `extractive_answer` / `ask` | 摘录、证据约束提示、模型回退和引用编号检查 |
| `raglab/evaluate.py` | Hit@K、MRR@K 与无答案题评测 |
| `server.py` | JSON 接口、本地 HTTP 服务和参数校验 |
| `web/app.js` | 问答、原文高亮、实验与评测 UI |

更细的讲解、练习与教师用步骤见 [LEARNING.md](LEARNING.md)。

### 检索的几个精确约定

- BM25：`k1 = 1.5, b = 0.75`，查询项去重；只对选中的资料范围计算 IDF。
- TF-IDF：`idf = log((N+1)/(df+1))+1`，`tf = 1+log(count)`；字组是词法特征，不是神经语义。
- 本地词法检索至少命中一个查询二元字组或英文词，避免仅因共享单个汉字召回；单字问题允许单字。语义向量不做该词法过滤。
- 每路取最多 `max(TopK*4, 20)` 个正分数候选，然后 `RRF = Σ 1/(60+rank)`；rank 从 1 开始，缺失名次贡献 0。
- Top K 后组装上下文，同源片段重叠超过较短跨度的 50% 时跳过；预算只统计原文字符，不统计问题、指令或 JSON 开销，也不等于 token 上限。完整块放不下就跳过。
- 本地摘录为每个来源选词语重合度最高的两句话，仅展示达到最佳句重合度 60% 的片段，最多三个来源。纯语义命中无词语重合时展示首个来源。它是阅读辅助，不能验证事实。
- 在线答案只检查 `[S数字]` 编号来自已提供证据。**编号合法不等于事实正确，也不证明引用内容支持该结论。**

## 评测与测试

```bash
python3 -m unittest discover -s tests -v
node --check web/app.js
```

自动测试涵盖核心数学、原文覆盖、持久化与并发去重、检索范围、上下文预算、语义索引失效、生成引用回退、格式提取和 HTTP 导入→问答→删除链路。HTTP 测试会临时监听本机端口；受限运行环境需允许本地监听。

“原理实验室”内可修改评测 JSON。匹配要求文件名一致，且召回片段包含标准短语；不只检查文档标题。Hit@K 表示前 K 是否命中；MRR@K 表示首个正确证据排名倒数的均值。无答案题单独统计“无候选率”，它不是最终回答的拒答准确率。

默认示例 Top 4 的 8 道有答案题命中率为 100%，MRR 为 1.0；2 道无答案题的无候选率为 50%。这个小评测集太简单，不能据此宣称产品准确率或混合检索一定更好。改变分块、资料范围或数据后，结果可能变化。保留失败题是为了展示误召回。

## 从个人工具到团队服务，还差什么

此版本绑定 `127.0.0.1`，限制 Host，写接口使用启动时令牌并检查 Origin，前端转义资料内容，模型请求不跟随重定向。它没有登录、服务端用户权限或租户隔离。页面“资料范围”只用于实验，**不是授权机制**。

在多人网络环境部署前，需要身份认证、检索前权限过滤、TLS、审计、备份、配额与异步导入任务。大量资料应换成持久化向量索引并引入重排序。本版逐次扫描选中片段，适合小库，不适合百万级片段。

文档提示注入通过指令隔离降低风险，但不能保证模型不会受影响。它没有执行工具或自动操作能力。拒答、版本有效性、事实一致性都需要独立的评测与后续实现，不能靠更长的提示词代替。
