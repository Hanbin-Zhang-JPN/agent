# easy_rag — 现代化、可解释、零依赖的白箱 RAG

一套 **标准库即可运行** 的检索增强生成（Retrieval-Augmented Generation）参考实现。
从「文档入库 → 切块 → 建索引 → 混合检索 → 重排 → 大模型生成」全流程**每一行都看得懂、改得动**，
不依赖任何外部黑盒库，适合学习 RAG 原理、二次开发或作为教学基线。

> 目录命名刻意保持简短直观：`rag`＝核心源码，`web`＝网页版，`data`＝示例文档，`out`＝索引输出。

---

## 1. 为什么要做这个项目

- **拒绝黑盒**：很多 RAG 框架把检索、向量化、排序封在晦涩的库里，出问题无从排查。
  本项目把每个环节都用朴素代码实现并逐行注释，原理透明。
- **真的能跑、能落地**：不是演示骨架，而是具备「混合检索 + 重排 + 引用溯源 + 评测」
  的完整工程，可以拿来接真实文档与真实大模型。
- **零门槛运行**：核心功能只用 Python 标准库，`pip` 都不用装就能跑通全流程。
- **中文友好**：对中文不依赖 jieba 等分词库，用「单字 + 二字组」规则分词，天然免疫新词。

```
├── web/

```

## 3. 整体工作流程

```
文档文件夹
   │  ingest.load_folder()   读取 txt/md/html/csv/docx/pdf
   ▼
全文文本
   │  chunk.chunk_text()     按句子切块 + 重叠衔接
   ▼
若干文本块
   │  index.add_documents()  分词、建 BM25 倒排、生成稠密向量
   ▼
本地索引（out/index.pkl）   ←── finalize() 计算 IDF / 归一化 / 保存
   │
   │  提问："退款政策是什么？"
   ▼
rank.hybrid_search()  ──►  BM25 精准匹配  +  稠密向量宽松匹配
   │                          │                 │
   │                          └── RRF 融合 ◄───┘
   ▼
候选段落
   │  rank.rerank()          词面重合度 + 向量相似度 二次打分
   ▼
Top-K 段落
   │  pipeline._build_prompt()  编号资料 + 系统提示
   ▼
大模型（OpenAI 兼容接口）──►  带 [n] 引用标注的答案
```

## 4. 核心原理（每一环都透明）

| 环节 | 做法 | 说明 |
|------|------|------|
| 分词 | 规则分词 | 英文按连续字符整词小写；中文取「单字 + 相邻二字组」，无需分词库 |
| 切块 | 句子边界 + 重叠 | 先按句末标点/换行切句，尽量聚到目标长度，相邻块重叠 100 字符防切碎 |
| 向量化 | 哈希 n-gram 嵌入 | 词元 crc32 哈希 → 取模累加到固定维度向量，符号交替减少碰撞，L2 归一化 |
| 倒排索引 | BM25 | 词元→文档倒排链，检索只遍历相关链；idf 平滑、词频饱和、长度归一化 |
| 混合检索 | BM25 + 稠密 + RRF | BM25 保字面精准，稠密向量容错表记差异；RRF 按位次融合两种排序 |
| 重排 | 词面重合度 + 向量相似 | 对候选块二次打分（重合度权重更高），输出最终顺序 |
| 生成 | OpenAI 兼容接口 | 只用 urllib 调 `/chat/completions`，协议透明，支持普通与流式 |

> **为什么用哈希嵌入而不是真实语义模型？**
> 因为要保证「零黑盒依赖、可复现、离线可跑」。哈希嵌入表达的是**字面/表记相似**，
> 对中文词序与常见改写有不错的容错。若业务需要真正的语义理解，
> 可以在 `embed.py` 中把 `embed_tokens` 替换为任意外部 embedding 模型
> （参考第 7 节「扩展点」），检索主流程无需改动。

## 5. 快速开始

```bash
# 1) 进入项目目录
cd easy_rag

# 2) 建库（读取 data/sample 下的示例文档，生成索引到 out/index.pkl）
python3 app.py build

# 3) 纯检索（不调用大模型，先看检索质量）
python3 app.py ask "退款政策是什么？" --no-llm

# 4) 检索质量评测（期望关键词是否出现在前 5 个结果中）
python3 app.py eval

# 5) 配置大模型后问答（不配置则自动退化为"仅检索"）
export LLM_API_KEY=sk-xxxx            # 填入你的密钥
python3 app.py ask "星云科技是哪一年成立的？"

# 6) 交互式对话
python3 app.py chat

# 7) 本地网页版（浏览器打开 http://127.0.0.1:8080）
python3 app.py serve --port 8080
```

## 6. 配置说明（config.py）

| 参数 | 默认值 | 作用 |
|------|--------|------|
| `EMBED_DIM` | 2048 | 稠密向量维度，越大碰撞越少、越占内存 |
| `K1` / `B` | 1.5 / 0.75 | BM25 词频饱和 / 长度归一化参数 |
| `TOP_K` | 5 | 默认召回段落数 |
| `RRF_K` | 60 | RRF 融合平滑常数 |
| `CHUNK_SIZE` | 500 | 切块最大字符数 |
| `CHUNK_OVERLAP` | 100 | 相邻块重叠字符数 |
| `LLM_BASE` | OpenAI | 任意兼容 `/v1/chat/completions` 的服务地址 |
| `LLM_MODEL` | gpt-4o-mini | 模型名，按实际服务修改 |
| `LLM_API_KEY` | 读环境变量 | 从 `LLM_API_KEY` 读取，代码不写死密钥 |

> **接入其它大模型**：把 `LLM_BASE` 改为目标服务根地址即可。
> 例如 DeepSeek：`https://api.deepseek.com/v1`、模型 `deepseek-chat`；
> 本地 Ollama：`http://127.0.0.1:11434/v1`、模型 `qwen2.5:7b`（本地服务无需密钥）。

## 7. 依赖与扩展点

### 依赖情况
- **强制依赖：无**。核心全流程仅用 Python 标准库（`re / math / os / json / pickle / zlib / zipfile / csv / html.parser / urllib / http.server`）。
- **可选加速：numpy**。装了 numpy 后稠密检索用矩阵乘法批量计算，速度更快；没装自动走纯 Python 兜底，结果一致。
  安装方式：`pip3 install numpy`（若不装也完全可用，只是检索稍慢）。

### 扩展点（已预留接口，按需替换）
| 想替换/增强的环节 | 改哪里 | 怎么做 |
|------------------|--------|--------|
| 换真实语义 embedding | `rag/embed.py` | 把 `embed_tokens` 替换为 sentence-transformers 等模型的向量输出即可 |
| 换大模型供应商 | `config.py` 的 `LLM_BASE/LLM_MODEL` | 指向任意 OpenAI 兼容服务 |
| 更多文档格式 | `rag/ingest.py` | 在 `_SUPPORTED` 与 `load_document` 中注册新解析器 |
| 更优的切块 | `rag/chunk.py` | 可替换为基于标题/语义的切块策略 |
| 分布式 / 超大规模 | `rag/index.py` | 把 `Index.save` 的 pickle 换成数据库或专用向量库持久化 |

## 8. 局限与后续方向

- **向量是"字面相似"**：哈希嵌入不是真正的语义模型，对同义改写、跨语言、抽象问题覆盖有限；
  正式场景建议接真实 embedding 模型（见扩展点）。
- **PDF 提取为尽力而为**：仅支持简单文本型 PDF（流对象 + Tj/TJ 文本），扫描件/复杂版式
  建议改用 `pypdf` 等专业库后再入库。
- **单机单进程**：当前索引保存在内存并持久化为单个 pickle 文件，适合万级以下文档；
  更大规模建议改用磁盘型向量库。
- **无在线增量更新**：新增文档需重新 build；可在 `add_documents` 基础上扩展增量保存。

## 9. 常见问题（FAQ）

- **运行时报 `No module named 'rag'`**：请在项目根目录（`easy_rag/`）下运行命令。
- **`ask` 不输出答案只给检索结果**：说明未检测到有效的 `LLM_API_KEY`，且接口不是本机服务；
  配置密钥或改用本地服务即可，也可用 `--no-llm` 明确只要检索。
- **建库后改了文档不生效**：重新运行 `python3 app.py build` 重建索引。
- **`numpy` 没装会不会报错**：不会，代码已做 `try/except` 自动降级，只是稍慢。
