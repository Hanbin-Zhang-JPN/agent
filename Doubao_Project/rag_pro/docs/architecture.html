rag_pro —— RAG 链路架构总览

从「文档入库」到「答案生成」共 6 个环节，右侧标注对应源码模块；全部用 Python 标准库实现，每行中文注释。

0

文档入库

ingest.pyreader.pychunker.pybm25.pyembedder.py

扫描目录 → 读取 txt/md/docx/pdf → 智能切块（段落+句子边界+重叠）→ 建立 BM25 倒排索引 → 向量化并写入向量库 → 持久化到 store/。读取与切块用线程池并行。

1

查询处理

query.py

可选：大模型把口语改写为规范问法（失败自动回退）；再用语料共现词做离线扩展，提升"说法不同但意思相同"的召回。

2

混合检索（双路召回 + RRF 融合）

retriever.pybm25.pyvectorstore.pyembedder.py

BM25 关键词路（精确术语/稀有词）+ 向量语义路（同义词/上下文），两路结果用 RRF（倒数排名融合）按名次融合排序。

3

精细重排 + 多样性

reranker.py

综合 BM25 分、向量相似度、位置先验、查询词直接命中率加权打分；可选 MMR（最大边际相关）避免选中的块内容重复。

4

上下文组装

context.py

去重 → 按 token 预算裁剪 → 给每段编号并标注来源 → 生成带引用 [1][2]… 的参考材料。

5

答案生成

generator.pyllm.py

默认离线抽取式（无 Key 可用）；配置大模型后自动切换为生成式，提示词强约束"只依据材料、引用编号、不知道就明说"以降低幻觉。

6

对外出口：答案 + 引用 + 可评测

pipeline.pycli.pyserver.pyeval.py

pipeline.ask() 串起全流程；命令行 / HTTP API 供外部调用；eval 用 Recall@k / MRR@k / Hit@k 量化检索质量。

标 ● 说明：本图与 README「3.1 一条问答请求在系统里如何流转」一致；核心链路仅用标准库，唯一外部调用是可选的「语义向量 / 大模型 API」，见 config.json 与 net.py。
