# rag_pro —— 现代化、可落地的「白箱」RAG

一套**全部用 Python 标准库实现、每一行代码都有中文注释、原理完全透明**
的检索增强生成（RAG）参考工程。它不是一个演示骨架，而是一条
**从文档入库 → 切块 → 建索引 → 混合检索 → 重排 → 上下文组装 → 生成答案**
都能真正跑起来、能接真实文档与真实大模型的完整链路，并自带**检索评测**，
用数据证明"能不能实际解决问题"。

> 一句话定位：**想看懂 RAG、想改 RAG、想把它接到自己文档上**，从这里开始。

---

## 1. 这个项目要解决什么问题

大语言模型直接回答问题有两个硬伤：**知识旧**（训练数据有截止时间）和
**爱编造**（幻觉，一本正经胡说八道）。RAG 的思路是：回答前先从你自己的
知识库里检索出相关资料，再让模型"看着资料回答"，从而做到
**答案可追溯、知识可随时更新、大幅减少幻觉**。

但市面上多数 RAG 框架（LangChain、LlamaIndex 等）把检索、向量化、排序
封在厚重的黑盒里，出了问题无从排查、想改无从下手。本项目反其道而行：
**把每个环节都用朴素代码实现并逐行注释**，同时保留"现代 RAG 该有的能力"：

- 混合检索（BM25 关键词 + 向量语义，RRF 融合）
- 精细重排 + MMR 多样性
- 查询改写 / 语料扩展
- 上下文组装（去重、token 预算、引用溯源）
- 离线抽取式 + 在线大模型双生成模式
- 检索质量评测（Recall@k / MRR@k / Hit@k）
- HTTP API 服务 + 命令行，可直接接入使用

## 2. 技术选型与"零黑盒"承诺

| 关注点 | 本项目的做法 |
|--------|--------------|
| 第三方依赖 | **核心零依赖**：只用 Python 标准库（`re/json/math/urllib/http.server/zipfile/zlib`…），无需 `pip install` |
| 分词 | 自实现：中文"单字 + 二字组" + 英文整词小写，免疫新词，不依赖 jieba |
| 切块 | 自实现：段落感知 + 句子边界 + 滑动重叠 |
| 检索 | 自实现：Okapi BM25 倒排索引 + 余弦相似度向量库 + RRF 融合 |
| 重排 | 自实现：多信号加权打分 + MMR 最大边际相关 |
| 向量化 | 内置 TF-IDF 稀疏向量（离线可用）；可选接语义向量 API |
| 生成 | 离线抽取式（无需任何服务）；可选接大模型 API |
| 网络 | 标准库 `urllib` 手写 JSON 请求，逻辑在 `rag/net.py` 一眼可见 |

**唯一可能的外部依赖**是"语义向量 API"和"大模型 API"（OpenAI 兼容协议）。
大模型本身无法从零实现，必须调用外部服务——这是刻意的、被记录在案的取舍，
而不是偷偷塞进来的黑盒：

- 何时调用、请求头、请求体、响应解析，全部写在 `rag/net.py`、`rag/embedder.py`、
  `rag/llm.py` 的注释里；
- **不配置 API 也能完整运行**（自动降级为内置向量 + 离线抽取式回答），
  因此即便没有任何外部服务，你也可以立刻体验、调试、测试全流程；
- 想接入任意 OpenAI 兼容服务商（豆包、硅基流动、DeepSeek、OpenAI…），
  只需在 `config.json` 里填 `base_url / api_key / model` 三项。

## 3. 目录结构与模块详解

```
rag_pro/
├── README.md           # 本说明文档（项目目的与详细组成）
├── run.py              # 一键入口：python run.py <命令>（转发到 rag/cli）
├── config.json         # 全局配置（检索/重排/向量/大模型参数）
├── requirements.txt    # 依赖说明（全部可选，核心零依赖）
├── .gitignore          # 忽略索引产物与缓存
├── rag/                # ★ RAG 核心源码包（重点阅读对象）
│   ├── __init__.py     # 包入口，导出 RagPipeline 等
│   ├── tokenizer.py    # 分词器：中文单字/二字组 + 英文整词（零依赖）
│   ├── chunker.py      # 切块器：段落感知 + 句子边界 + 重叠
│   ├── reader.py       # 文档读取：txt/md/docx/pdf（全标准库）
│   ├── bm25.py         # Okapi BM25 倒排索引（自实现）
│   ├── vectorstore.py  # 稠密/稀疏向量库 + 余弦相似度（自实现）
│   ├── embedder.py     # 向量化：内置 TF-IDF 稀疏向量 / 可选语义向量 API
│   ├── net.py          # 网络请求工具（唯一对外网络层）
│   ├── retriever.py    # 混合检索：BM25 + 向量 + RRF 融合
│   ├── reranker.py     # 重排：多信号打分 + MMR 多样性
│   ├── query.py        # 查询处理：大模型改写 + 语料扩展
│   ├── context.py      # 上下文组装：去重 + token 预算 + 引用编号
│   ├── llm.py          # 大模型客户端（OpenAI 兼容，urllib 实现）
│   ├── generator.py    # 答案生成：离线抽取式 / 大模型生成式
│   ├── ingest.py       # 入库管线：发现→读取→切块→索引→向量化→持久化（并行）
│   ├── pipeline.py     # RAG 主流程：把上面所有模块串成 ask()
│   ├── server.py       # HTTP API 服务（标准库 http.server）
│   ├── eval.py         # 检索评测：Recall@k / MRR@k / Hit@k
│   └── cli.py          # 命令行入口
├── data/
│   └── sample/         # 示例文档（一个关于 RAG 本身的小知识库）+ 评测集
├── store/              # 索引输出目录（运行时生成，已 gitignore）
└── tests/
    └── test_rag.py     # 单元测试（unittest，覆盖核心模块与离线全流程）
```

### 3.1 一条问答请求在系统里是如何流转的（建议先看这段）

```
用户问题
  │
  ▼
① 查询处理 query.py        —— 可选大模型改写 + 语料关联扩展
  ▼
② 混合检索 retriever.py    —— 双路召回：BM25(词法) + 向量(语义)，RRF 融合
  ▼
③ 重排 reranker.py         —— 多信号加权打分（词法/向量/位置/精确命中）+ MMR 去重
  ▼
④ 上下文组装 context.py    —— 去重、按 token 预算裁剪、编号并标注来源
  ▼
⑤ 答案生成 generator.py    —— 离线抽取式（默认）/ 大模型生成式（可选）
  ▼
  答案 + 引用溯源 [1][2]…
```

### 3.2 核心模块设计说明

- **分词器（tokenizer.py）**：中文无空格，采用"单字 + 相邻二字组"策略。
  二字组能匹配"检索""切块"这类中文复合词，天然覆盖新词，不需要词典；
  英文与数字整词小写化，`RAG` 与 `rag` 互相命中。
- **BM25（bm25.py）**：完整的 Okapi BM25，含倒排索引、TF/IDF/长度归一化、
  词频饱和；另外实现了基于"共现"的相关词挖掘，供查询扩展使用。
- **向量库（vectorstore.py）**：余弦相似度用朴素点积实现，支持
  稀疏字典（内置向量）与稠密列表（语义向量）两种表示，兼容混用。
- **混合检索（retriever.py）**：双路召回后用 RRF 融合，只依赖名次、
  不依赖原始分数，稳定且可解释。
- **重排（reranker.py）**：把词法分、向量分、位置先验、精确命中率
  加权求和，再可选做 MMR 多样性筛选，避免选中的块内容重复。
- **查询处理（query.py）**：可让大模型把口语改写为规范问法（失败自动回退），
  再用语料共现词做离线扩展，提高"说法不同但意思相同"的召回。
- **生成器（generator.py）**：离线抽取式从命中的块里抽出关键句并附引用，
  适合调试检索与无 Key 场景；大模型式通过强约束提示词（只依据材料、
  引用编号、不知道就明说）降低幻觉。
- **评测（eval.py）**：给定"问题 → 标准来源"，量化计算 Recall@k / MRR@k /
  Hit@k，让你改完算法能立刻看到是变好还是变差。

## 4. 快速开始

```bash
# 0) 进入项目（本项目零第三方依赖，Python 3.8+ 即可，无需 pip install）
cd rag_pro

# 1) 构建索引（默认读取 data/sample 示例知识库，输出到 store/）
python run.py build --dir data/sample

# 2) 单次问答（离线抽取式，无需任何 API）
python run.py ask --q "什么是RAG？"
python run.py ask --q "RRF融合的原理是什么？"

# 3) 交互式问答
python run.py chat

# 4) 检索评测（用数据说话：看检索能不能找到正确来源）
python run.py eval --qa data/sample/qa.json

# 5) 启动 HTTP API 服务（另开一个终端）
python run.py serve --port 8765
#    接口：GET  /health         健康检查
#          POST /query          {"question":"..."}  问答
#          POST /ingest         {"path":"文档目录"}  增量入库
#          GET  /info          索引信息

# 6) 查看索引信息
python run.py info

# 7) 跑单元测试
python -m unittest discover -s tests -v
```

> 也可以用 `python -m rag.cli build ...` 代替 `python run.py ...`，二者等价。

### 4.1 接入你自己的文档

1. 把文档（支持 `.txt / .md / .docx / .pdf`）放进某个目录；
2. 重新构建索引：`python run.py build --dir <你的目录>`；
3. 开始问答：`python run.py ask --q "你的问题"`。

### 4.2 接入真实大模型（可选，增强回答质量）

编辑 `config.json`，填入任意 OpenAI 兼容服务商的信息：

```json
{
  "embed": { "mode": "auto", "base_url": "https://...", "api_key": "sk-...", "model": "text-embedding-v4" },
  "llm":   { "base_url": "https://...", "api_key": "sk-...", "model": "doubao-pro-32k" }
}
```

- `embed.mode = "auto"` 时会自动检测：配置齐全 → 用语义向量；否则 → 内置向量；
- `llm` 配置齐全后，生成阶段自动切换为大模型生成式（`gen_mode` 默认 `auto`）。

## 5. 性能与可扩展性说明

- **入库并行**：读取 + 切块阶段用线程池（默认 8 线程）并行处理；
- **向量缓存**：语义向量按文本指纹缓存到磁盘，重复内容不重复请求、不重复计费；
- **混合检索 + 重排**：相比单一检索方式，对精确术语与语义表达都更稳；
- **评测闭环**：改任何参数后跑 `eval` 即可量化对比，避免凭感觉调参。

**规模定位与扩展方向**（诚实说明边界）：
- 当前向量库采用线性扫描，适合**数千到数万块**的中小规模知识库（本地秒级返回）；
- 若要支撑百万级向量，建议把 `vectorstore.py` 的检索替换为
  HNSW / 倒排量化等 ANN 索引（接口已隔离在 `search()` 一个方法里，替换成本低）；
- 若要支持多租户 / 权限 / 在线更新，可在 `ingest.py` 与 `server.py` 之上扩展。

## 6. 已知限制（不回避问题）

1. **PDF 解析是"够用"级别**：内置抽取器只处理最常见的 FlateDecode 文本流，
   对复杂排版、扫描件（无文本层）可能抽不全；这类文件建议先转 txt/md 再入库。
2. **内置哈希向量不是语义向量**：它本质是带权词袋，能匹配字面相关，
   但理解同义词需要配置语义向量 API（`config.json` 的 `embed`）。
3. **无在线增量更新**：当前 `build` 是全量重建；文档量很大时，
   建议按批次入库或自行扩展增量逻辑。
4. **HTTP 服务面向本地/内网**：标准库 `http.server` 够用且透明，
   若要高并发生产部署，建议换成 FastAPI/uvicorn（接口结构不变）。

## 7. 常见问题（FAQ）

**Q：必须装依赖吗？**
A：不需要。核心全部用 Python 标准库，`pip` 都不用装。只有接语义向量 /
大模型 API 时才需要网络与 API Key。

**Q：没 API Key 能体验吗？**
A：能。默认走"内置向量 + 离线抽取式回答"，全流程可跑、可测、可改。

**Q：想深入理解 RAG，先看哪个文件？**
A：推荐顺序：`README`（整体）→ `rag/pipeline.py`（主流程）→
`rag/retriever.py`（检索）→ `rag/bm25.py`（BM25）→ `rag/generator.py`（生成）。

**Q：跟 easy_rag / rag_kit 是什么关系？**
A：`rag_pro` 是本项目目录下的独立全新工程，与同目录其他 RAG 项目互不影响；
它把"混合检索 + 重排 + 查询扩展 + 评测 + HTTP API"做成了更完整、更现代的形态。
